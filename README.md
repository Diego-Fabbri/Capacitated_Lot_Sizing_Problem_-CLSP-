# Capacitated Lot Sizing Problem (CLSP)

A **Mixed Integer Linear Programming (MILP)** model in **Java** for the **single-item Capacitated Lot Sizing Problem**, built with the **IBM ILOG CPLEX 12.5** optimization engine via the CPLEX Java API.

## Overview

The Capacitated Lot Sizing Problem (CLSP) is a classic production planning problem in Operations Research. Given a single product, a planning horizon of discrete periods, and a production capacity per period, the goal is to decide **how much to produce in each period** in order to satisfy known demand at minimum total cost — balancing setup costs, unit production costs, and inventory holding costs.

The problem is called *capacitated* because production in any period is bounded by a maximum lot size $C_t$. When $C_t$ is large enough to cover total demand, the capacity constraint becomes non-binding and the problem reduces to the **uncapacitated lot sizing problem (ULSP)**, which this instance effectively represents.

## Mathematical Formulation

### Sets

- $T$ = the planning horizon (index $t = 0, 1, \dots, n$)

### Parameters

- $d_t$ = the demand forecast at time $t$
- $c_t$ = the unit production or purchasing cost at time $t$
- $h_t$ = the unit inventory cost at time $t$
- $K_t$ = the fixed setup or ordering cost at time $t$
- $C_t$ = the maximum feasible lot size (capacity) at time $t$

### Variables

- $q_t$ = quantity to be produced or ordered during period $t$; $\forall\, t \in T \setminus \{0\}$
- $I_t$ = inventory level at the end of period $t$; $\forall\, t \in T$
- $y_t$ = binary setup variable:

$$
y_t = \begin{cases} 1 & \text{if units of the product are manufactured/ordered in period } t \\ 0 & \text{otherwise} \end{cases}
$$

### Objective Function

**(1)** — Minimize total cost (setup + production + inventory)

$$
\displaystyle \min \sum_{t=1}^{n} \left( K_t \cdot y_t + c_t \cdot q_t + h_t \cdot I_t \right)
$$

### Constraints

**(2)** — Inventory is zero at the start and end of the horizon

$$
I_t = 0 \qquad t = 0 \ \text{and} \ t = n
$$

**(3)** — Demand satisfaction and inventory balance

$$
q_t + I_{t-1} = d_t + I_t \qquad \forall\, t \in T \setminus \{0\}
$$

**(4)** — Production is capped by capacity and linked to the setup decision

$$
q_t \le C_t \cdot y_t \qquad \forall\, t \in T \setminus \{0\}
$$

**(5)** — Non-negative production

$$
q_t \ge 0 \qquad \forall\, t \in T \setminus \{0\}
$$

**(6)** — Non-negative inventory

$$
I_t \ge 0 \qquad \forall\, t \in T \setminus \{0\}
$$

**(7)** — Binary setup variable

$$
y_t \in \{0, 1\} \qquad \forall\, t \in T \setminus \{0\}
$$

> **Note on capacity:** The problem is uncapacitated when $C_t \ge \sum_{t \in T} d_t$. In this instance, $C_t = 10{,}000$ for all periods while total demand is 700, so the capacity constraint (4) is never binding. Reducing $C_t$ to realistic values would activate the constraint and potentially change the optimal solution.

A copy of this formulation is available as both a PDF and a LaTeX source file in this repository.

## Example Instance

The program solves a hardcoded instance featuring **1 item** over **6 demand periods**:

| Period $t$ | Demand $d_t$ | Setup cost $K_t$ | Unit prod. cost $c_t$ | Holding cost $h_t$ | Capacity $C_t$ |
|:---:|---:|---:|---:|---:|---:|
| 1 | 60 | 180 | 7 | 1 | 10,000 |
| 2 | 100 | 140 | 7 | 1 | 10,000 |
| 3 | 140 | 160 | 8 | 2 | 10,000 |
| 4 | 200 | 160 | 7 | 2 | 10,000 |
| 5 | 120 | 170 | 6 | 2 | 10,000 |
| 6 | 80 | 190 | 10 | 2 | 10,000 |

The included `Capacited_Lot_Sizing.log` records the full solution. The **optimal total cost is 5,650**, found in **0.08 seconds**. The optimal production plan batches demand across periods to avoid paying setup costs every period:

| Period $t$ | Produce $q_t$ | Inventory $I_t$ | Setup $y_t$ |
|:---:|---:|---:|:---:|
| 1 | 60 | 0 | ✅ |
| 2 | 240 | 140 | ✅ |
| 3 | 0 | 0 | ❌ |
| 4 | 200 | 0 | ✅ |
| 5 | 200 | 80 | ✅ |
| 6 | 0 | 0 | ❌ |

Periods 3 and 6 are served from the inventory accumulated in the previous period, avoiding their setup costs (160 and 190 respectively). Period 2 produces 240 units covering both its own demand (100) and period 3's demand (140).

## Requirements

- **Java** 13 or later
- **Apache Maven** 3.x
- **IBM ILOG CPLEX** 12.5 — must be installed separately and added to the local Maven repository as `External_Libraries:Cplex:12.5`

> CPLEX is a commercial solver. An academic license is available free of charge through the [IBM Academic Initiative](https://www.ibm.com/academic).

## Setup

1. Clone the repository:
   ```bash
   git clone https://github.com/Diego-Fabbri/Capacitated_Lot_Sizing_Problem_-CLSP-.git
   cd Capacitated_Lot_Sizing_Problem_-CLSP-
   ```

2. Install the CPLEX JAR into your local Maven repository:
   ```bash
   mvn install:install-file \
     -Dfile=<path-to-cplex.jar> \
     -DgroupId=External_Libraries \
     -DartifactId=Cplex \
     -Dversion=12.5 \
     -Dpackaging=jar
   ```

3. Build and run with Maven:
   ```bash
   mvn clean package
   mvn exec:java
   ```

   Or open the project directly in **NetBeans IDE** and use the pre-configured run action (`nbactions.xml`).

## Output

When executed, the program:
- Builds the MILP model programmatically using the CPLEX Java API
- Solves it and prints the solver status and optimal total cost
- Exports the model in LP format (`Capacited_Lot_Sizing.lp`)
- Writes the solver log to `Capacited_Lot_Sizing.log`, including:
  - Branch-and-cut progress and gap evolution
  - Optimal objective value (minimum total cost)
  - Production quantity $q_t$, inventory level $I_t$, and setup decision $y_t$ for each period
